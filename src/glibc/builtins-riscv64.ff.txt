  comment
    libgcc_eh's unwinder as far as glibc asks it (a static program has it from gcc: __pthread_unwind's _Unwind_ForcedUnwind with unwind_stop, which reads _Unwind_GetCFA; backtrace's _Unwind_Backtrace and _Unwind_GetIP), for ttpc's frames on
    riscv64:
    each C function's s0 holds its caller's s0, s0 + 8 its return address, s0 + 16 its CFA (a variadic one's is 64 bytes higher: an unwind_stop that compares it is early by one frame there). An asm function keeps its caller's s0, so a walk goes
    past it, a signal handler's to the frame the signal stopped.
    The walk begins at the caller's frame, ends where the next s0 is 0 or not above the last (the end of the stack: _start's, whose s0 the kernel left 0); its stop function sees each frame (the last with _UA_END_OF_STACK), unwind_stop longjmps
    out of it.
    gcc's own unwinder, which reads .eh_frame (ttpc -g writes it, debug.pl and ehframe.pl), is C++'s: this one runs no personality routines (ttpc writes no LSDA), as glibc's C needs none, its cleanups are registered
    (pthread_cleanup_combined_push, the jmp_bufs of pthread_cleanup_push).
