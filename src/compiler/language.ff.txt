ff, the language ttpc compiles
  the tree
    a node holds one thing, its content (at most 255 bytes, any bytes, no NUL), and at most 255 children
    the root's children are pages; ttpc reads several trees, the pages of all but the last, then the last whole as the program
    .ff is the binary tree (sicompass), .ff.txt its text form, two spaces per level (fftext.pl)
  names
    a node whose content ends in a colon is a function (a definition); any other node is a call, its children the arguments, bound by position
    a function's leading leaf children are its parameters, the rest its body
    a name may hold spaces (een variabele, else if, compile time)
    a register is a definition whose name has a space and whose first child is a bit string, each word one of its names
      example
        x10 a0:
          01010
    scope: a name's place in the tree
      a definition is seen in the subtree of its parent: by its siblings and everything below them, nowhere else
      a name is looked up from where it stands, up the tree, innermost first: its siblings, its parent's siblings, and so on; then the program page, the target's section, the shared page
      an inner definition hides an outer one of the same name; the same name under two parents is two names
      example
        a:
          j
            done
          done:
            ret
        b:
          j
            done
          done:
            ret
      a group's children are local to the group; a section is the exception: calling it puts the definitions of its groups in scope
      a function whose name is only digits (0: 1: 2: ...) is a layer, the overflow of its parent past the 255 children a node holds: its children count as the parent's, in every scope, code and labels too
        a layer may hold layers, each level 255 more children
        a layer is never a name itself
        example
          0:
            a:
              ret
            0:
              b:
                ret
          1:
            c:
              call
                a
              call
                b
              ret
      first the function, then the call
  pages
    every page but the last holds definitions: instructions, macros, constants, sections
    the last page is the program: its functions are placed labels, block form, they hold the code up to the next label; nested ones are local
    two passes: the first finds the labels, the second emits
    a program page without origin or elf_header of its own is wrapped in the target's frame (origin, ELF header, program, file_end, bss, mem_end)
    include path, first on a program page, reads that tree and puts its pages in front of the program, each path once, from the folder of the tree
      a folder with an index.ff is a library, read lazily: only the files of what the program reaches (index.ff is a page index: of name: / file)
  asm
    operands go in the reverse of GNU as, the destination last (stores aside)
      example
        addi
          5
          zero
          a0
    an encoding is a function whose body holds only fields, fixed name: bits and slices imm[11:0] imm, 8 to 64 bits: an instruction or a data word
    a call of an encoding emits it, a call of another function expands it as a macro
    contexts: code (encode and emit, or expand), field (the fields of an encoding, MSB first), exec (at assemble time, on virtual registers, riscv64's ALU ops)
    an argument is, in this order, a nested call (run in exec, its value a0), a number (decimal or 0x), a parameter, a register, pc, a label, a constant (a function without parameters, run in exec)
    range checks: every operand must fit its slices
    builtins: comment, ascii, align, reserve, origin, bss, size, include
      comment text: anywhere, never evaluated; after a function's parameters
      ascii bytes: emits its argument's content as it is
      align n, reserve n, origin n, bss, size label
  targets
    ttpc --target riscv64|x86_64|aarch64|arm; riscv64 without it
    the shared page holds what every target has (byte half word dword bits rel), the builtins declared, then one section per target, groups inside
    the shared page ends in a compile time lambda that calls the section --target names; calling a section puts its definitions in scope
    a program is assembled with the target's definitions, compile time with the host's (the machine ttpc runs on)
  C
    a function on the program page whose first child is a type is C; C lowers to the primitives of the target (cc_push, cc_jz, ...)
    a node holds one thing: one name, number, operator, type word; no text to parse, no quotes, no brackets
    items
      siblings without an operator between them are separate items: statements, arguments, elements
      an operator node joins its neighbours into one expression, with C precedence
      precedence, low to high: = += -= *= /= %= &= |= ^= <<= >>=, ? :, ||, &&, |, ^, &, == !=, < > <= >=, << >>, + -, * / %; leading - ! ~; ++ -- after a name, or before one
      x ++ is C's x++: x grows by one (an element, for an address), the value is the old x; ++ x is C's ++x, the value the new x; -- likewise
      && and || short-circuit; and, or are instructions (bitwise, with operands), never operators
      c ? a : b is C's conditional, a leaf ? and a leaf : among the siblings, right to left: c ? a : d ? e : f is c ? a : (d ? e : f), x = c ? a : b assigns it; only the branch taken is worked out
      its type is the branches' common type, both converted to it: C's usual arithmetic conversions (c ? u32 1 : - 1 is unsigned), a pointer beside 0 or a pointer the pointer, a struct the struct
      c ?: b, a ? and a : together, is GNU C's: the value of c when it is not 0 (c worked out once), else b
      the : of a ? is part of the item, it starts none; a : with children is a lambda there too, as a branch: c ? : a b : d
      example
        smaller:
          long
          x
          <
          y
          ?
          x
          :
          y
      an operator first in an item starts an expression, also first in a lambda: - ! ~
      example
        een variabele
        *
        3
      a negative value next to other items goes in a lambda, C's parentheses, or the - joins the item before it: if x < 0, its value - 1; a leaf -8 is a number itself
      example
        if
          x
          <
          0
          :
            -
            1
    types
      a type is a run of leaf siblings, one word per node, the first word first; a node with children ends the run
      scalars: char (1 byte, signed on x86_64, unsigned on riscv64, aarch64 and arm, as their ABIs say: the target's cc_char), short (2), int (4), long (a word of the target: 8, 4 on arm), i8 i16 i32 i64, u8 u16 u32 u64, void, va_list (a word)
      i64 and u64 are refused on arm
      T * pointer: a word, the address of a T, the base type and then * pointer, siblings, in C's order: char / * pointer is char *, char / * pointer / * pointer char **; void / * pointer the address of nothing (C's void *)
      a type run is its base, a type word (or an array node), and the * pointer leaves after it; it ends at the first node that is neither, so the items after it are never read as a type (a variable is never named as a type)
      array T n: n elements of T, the array node holding the element's type run and the count: (array / int / 3) is C's int [3]; n a number or a constant; no count is C's T [], no elements of its own
      the array node's * pointer after it is a pointer to the array: (array / int / 4) / * pointer is C's int (*)[4]; (array / char / * pointer / 5) is C's char *[5]; arrays of arrays nest, (array / (array / int / 4) / 3) is C's int [3][4]
      in a function n may be any value, worked out at run time (C's variable-length array): its n elements are on the stack until the function returns; alloca n (C on the shared page) likewise gives n bytes there
      a struct name is a type: point:, struct, then its fields, each name: and a type run, laid out as C does
      a list longer than a node holds (255) comes in groups, each an items word holding at most 255: a declaration's items, a : group's, an enum's constants
      float, double and long double are C's floating types, 4, 8 and 16 bytes on every target; a floating literal is an exact hex float, 0x1.8p+0, f after it for a float
      a long double literal has L after it, binary128's 113 bits: 0x1.921fb54442d18469898cc51701b8p+1L; a subnormal one is 0x0.<digits>p-16382L, zero 0x0p+0L
      + - * / and the comparisons work on them, - negates, cast: converts between them and to and from the integers, on every target
      a floating type larger than a word (long double; double on arm) is in memory as a struct is, a value of it the address of a temporary; arm works on its double with VFP
      long double's arithmetic calls soft-fp's functions, as gcc calls libgcc's: __addtf3 ... __getf2, __negtf2, __floatditf ... __trunctfdf2; the program has them (glibc's soft-fp)
      type (compile time only): a word of any type, as C++'s T
      example
        my string:
          char
          * pointer
          this is a string
      example
        grid:
          array
            array
              int
              3
            4
      example
        line:
          struct
          from:
            point
            * pointer
          to:
            point
            * pointer
      a struct may hold an address of itself or of a struct that holds one of it (next: node / * pointer): an address is a word, whatever it points to
      example
        node:
          struct
          value:
            long
          next:
            node
            * pointer
      a union name is a type: word:, union, then its fields as a struct's, all at 0, as large as the largest one, aligned as the most aligned
      a field : with a struct or union type and no name is an anonymous member (C11's): its fields are seen as the outer one's own, at its offset plus theirs
      example
        both:
          union
          :
            pair
          w:
            long
      a bitfield: a field's type run, then its width, a number: mode:, u32, 3; it is packed into units of its type as gcc does (one that does not fit the unit begins the next), read and written as that many bits, up to the whole unit (u64, 64)
      example
        flags:
          struct
          mode:
            u32
            3
          count:
            int
            24
      align / n, first under a field's name and before its type, places the field at a multiple of n, its record as aligned at least (C's aligned attribute)
      align / n right after struct or union aligns the record itself, its size a multiple of n; align only raises an alignment, as C's does
      example
        mcontext:
          struct
          gregs:
            array
              u64
              32
          fpregs:
            align
              16
            array
              u64
              66
      example
        pthread:
          struct
          align
            32
          tid:
            int
      an enum name is a type, an int: color:, enum, then its constants, each name:, with a value (a number or a constant, - before it) or one more than the one before, the first 0; a constant is seen where the enum is, on the page
      example
        color:
          enum
          red:
          green:
            5
          blue:
      a function type: compare:, function, its return type run, its parameters name: and a type; compare / * pointer is a pointer to such a function
      a variable or a global holding one, called with arguments, calls the function it points to; f / & address is a function's address
      without arguments it is called with a . after it, f / . (C's f ()): the variable alone is its value; a path to one likewise, p / fn / .
      a path that reaches one (a field, an element) calls it with the rest of the path as arguments: p / add / x / y is C's p->add (x, y), tab / 0 / add / x / y is tab[0].add (x, y)
      example
        binary:
          function
          long
          a:
            long
          b:
            long
        f:
          binary
          * pointer
          add
          & address
        x:
          long
          f
            3
            4
      sizeof and alignof: of a type run or a variable, an unsigned long
      sizeof of a variable-length array is its size in bytes, worked out where it is declared
    arithmetic, as in C
      char and short, signed or not, become int first
      then both operands get one type: of 8 bytes if either is (unsigned if an 8-byte one is), else unsigned int if either is one, else int
      a shift has the type of its left operand; a comparison and ! are int
      a value is as wide as its type: an int or an unsigned int wraps at 32 bits; what is stored, the value of = += -= ++ --, and a conversion are cut to their type
      a number is an int if it fits one, else a long; one in hex is the first that fits of int, unsigned int, long, unsigned long
      example
        u:
          u32
          0xffffffff
        zero:
          u32
          u
          +
          1
      not yet on arm, where long is 4 bytes: an unsigned int with a long is a long, not C's unsigned long
    declarations
      name:, a type run, then its items; the type is required, nothing is derived from the value
      a local in a function, a global at the top of the page
      a global's items are worked out while compiling: a number or constant, - and one, name / & address (of a global or a function), a text (cast / char / * pointer and a leaf, or the leaf alone for an address), a cast and its value, a : of one expression
      no items: zero
      one item on a scalar or an address: its value, converted to the type
      several items only on an array (one element each, the rest zero, more than n is an error) or a struct (one field each, in order)
      a field or element that is a struct, union or array takes a : holding its items, as C's inner braces; what has no item is zero, in a local too
      an empty : is a zero struct, union or array, as C's {}
      example
        pts:
          array
          point
          2
          :
            1
            2
          :
            3
            4
      a page item whose items have children only as :, items, a cast's type or the value after a cast, a suffix or before & address is a global, any other is a function
      each global ends padded to 8 bytes, so what follows a one-byte global (another global, a function's code) stays aligned
      thread local, first under a global's name and before its type, makes it thread-local: in the TLS image at its offset from the thread pointer (riscv64), else a global
      align / n, first under a global's name (before thread local or section), places the global at a multiple of n
      weak, first under a name and before its type, declares a global that may stay undefined (C's #pragma weak): its address is 0; weak / function / type is a function, called through 0
      constructor, first under a function's name and before its type, makes the start code run it before main (C's __attribute__ ((constructor)))
      ttpc lays a constructor's address out between __init_array_start and __init_array_end, which glibc's start walks, as ld does; each one of the program and of its library is compiled
      constructor / 101 gives it a priority, lower first, those without one last
      destructor, the same way, runs it at exit (C's __attribute__ ((destructor))): between __fini_array_start and __fini_array_end, walked from the end
      example
        init:
          constructor
          void
          ready
          =
          1
      example
        errno:
          thread local
          int
          0
      a scalar with several items is an error, so is a declaration without a type
      example
        n:
          long
          0

    text
      a leaf under char / * pointer (a declaration's item, or the value after a cast to it) is text, whatever it reads as (a number, a name): its bytes and a NUL are put in the program, the value is their address; (cast / char / * pointer), then 3, is "3"
      a text holds at most 255 bytes, a node's text: text leaves in a row are one text, as C's "ab" "cd"
      an array char n takes text leaves in a row for its items, as C's char s[16] = "hi", the rest 0 (in a global)
      char with text is an error (a local was silently a char / * pointer, a global a char array)
      as a value (an argument) it is a cast to char / * pointer and then the text; a value that is a variable goes in a : there
      example
        print
          cast
            char
            * pointer
          hello\n
    conversions
      cast, its type run its children, is C's cast, the value after it, the next sibling, converted to the type: (cast / char / * pointer), then p, is (char *) p; as a statement it is (void) x; every conversion is one
      cast is a prefix, as - is: its operand is the next sibling with its postfixes (cast / long, then p / * pointer, is (long) *p); an operand of several nodes goes in a :
      a typed literal is C's suffix, then the number: U 7 is 7U, L 5 is 5L, UL 2 is 2UL, LL 1 and ULL 1, of the types C gives them on the target (UL is 32 bits on arm); a negative leaf is a number, L -5
      example
        cast
          char
          * pointer
        :
          p
      example
        cast
          long
        x
      & address after a variable is its address, C's &x; * pointer after an address is what it holds, C's *p; both are postfixes, as ++, applied left to right: p / * pointer / * pointer is **p, x / & address / * pointer is x
      example
        cast
          long
        r
        & address
    functions
      name:, its return type run, its parameters, its statements
      a parameter is name: with a type run as its only children; no untyped leaf parameters
      the parameters are the leading such nodes: a local first in a body with only its type is one more parameter, so give it a value (r:, point, 0)
      a call is name with its arguments in order, the first 8 in the argument registers, the others on the stack; its value is what return gives
      a leaf ... after the parameters takes more arguments: va_list is a word, va_start ap points it at the first after the parameters, va_arg ap type takes one, va_end ap, va_copy to from
      an extra argument of a type kept in memory (a struct, long double) goes as its value, the address of its object; va_arg of that type is the object, which a declaration of it copies
      in such a function va_arg_pack, the last argument of a call to another one, passes its own extra arguments on, and va_arg_pack_len is how many there are (GNU C's __builtin_va_arg_pack), at run time
      example
        sum:
          long
          n:
            long
          ...

            0
          va_start
            ap
          s:
            long
            va_arg
              ap
              long

      a union name as a value, then a field's name, then its item, is one of a union: (union val){ .str = "x" } is val, str, x
      an array node with its count as a value, its count's items after it, is a temporary array, its value its address (C's (char *[]){ "sh", 0 } is (array / char / * pointer / 2), sh, 0)
      a place that is a struct, a union or an array takes its own type and its items in turn, as nested braces

            1
            2

      a struct goes by value: = copies it, a declaration with a struct of its type starts as a copy, an argument is the callee's own copy, a result is copied into space the caller keeps for it

          b

    scope
      the program page's functions and globals are seen everywhere on it, above and below their definition (two passes)
      a parameter is seen in its function's body
      a function's body, an if, else or while body and a lambda are blocks; a declaration is seen from below it to the end of its block, inner blocks too
      used above its declaration is an error, used after its block an unknown name
      a local hides a global or a parameter of the same name, an inner block's local hides the outer one; declared twice in one block, the later one counts
      a function does not see the locals of its caller
      example

          long
          1

            SYS_exit

    lambda
      a node : alone is an anonymous function run in place: a block with its own scope, or parentheses; its value is its last item
      as parentheses around one item it stands for that item, also on the left of = and under ++: : / x / = / 1 is C's (x) = 1
      example
        d:
          long
          :
            2
            +
            3
          *
          4
    paths
      calling a variable indexes or selects: xs i an element, p x a field (also through an address), r b x both in a row
      a path from a value that is not a variable: a . leaf among a node's children, the node before it (cut there) the value, the path after it; C's ((point *) p)->y is : / (cast / point / * pointer) / p / . / y, (*p).len is : / p / * pointer / . / len
      a : that holds one expression, a unit with a prefix or a postfix (cast / long, x; p / * pointer), is that expression, as C's parentheses: no scope of its own; so is one as the operand of a cast or of * pointer
      the address of a function is a function pointer, called where it stands, its result of the type its definition says: C's ((void) x, &f) (a, b) is : / (: / (cast / void) / x / f / & address) / . / a / b
      x / & address is C's &x, p / * pointer C's *p, read, or written on the left of =
    registers
      a register name in C is that register: reading t2 is its value now, t2 = expr writes it; values pass between C and asm this way
      C itself uses V, L, X (on riscv64 a0 t0 t1) and SP, FP; it does not write the fixed ones (on riscv64 zero ra sp s0)
    asm in C
      a node naming an instruction or macro of the target is emitted as it is; asm belongs to one target, guard it with compile time
    asm functions
      name: / asm / instructions is an asm function: its instructions (and block labels) are placed as the asm of a page, on a definition page only when C reaches it
      C calls it by name and takes its address, as a long; it keeps the calling convention itself (glibc's .S functions, by gen/s2ff.pl)
      align / n first after asm places the function at a multiple of n (glibc's ENTRY, .p2align: the nops inside it count from there)
      what its instructions name (a library function, C or asm, a C alias) is reached and placed before it, so asm names it by its label
      a block label whose first child is asm is one more entry of the function (glibc's _setjmp runs on into __sigsetjmp): C calls it and takes its address, and the function holding it is placed with it
      example
        seven:
          asm
          addi
            7
            a0
            a0
          ret
    reserved
      no variable, function or struct is named like a keyword, a type name (type), an operator or a register of the target
      the keywords: if, else, else if, while, for, do while, switch, case, default, goto, return, break, continue, comment, & address, * pointer, syscall, array, struct, enum, function, sizeof, alignof, union
      and: ..., va_start, va_arg, va_end, va_copy, thread local, constructor, destructor, alias, ifunc, asm, compile time, emit, fail, number, target
  compile time
    compile time goes only first in a named function or a lambda; elsewhere it is an error
    that function or lambda runs while compiling, natively on the host, once per node in pass 1, with the whole program page (C and asm); it is not in the program
    for it the page is compiled for the host too, so compile time can call its functions; there a lambda puts nothing and does not run: what it emits is the target's
    a named one without parameters is a define: its value is what a use of it gives
      example
        LINES:
          compile time
          3
    a named one with parameters is a macro; its parameters are typed, type for any
      example
        square:
          compile time
          x:
            type
          x
          *
          x
    a compile time function has no return type: its value is a word, a long
    a lambda with compile time is #if and generated code: only what it emits is in the program; its value is its last item
    emit subtree... puts the subtrees in the program where the lambda stands; number expr in them becomes that number
    fail item... stops the compile and prints its items; target is the section --target named
    example
      :
